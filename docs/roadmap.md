# Roadmap

## Release candidate 0.1.0

Implemented: bilingual local playground, calendar/manual input, transparent relationships, Zi-hour comparison, optional cycles, exports and regression checks. Public launch and independent use remain separate validation steps.

## Next only when a real use case supports it

1. An independently sourced boundary fixture set, including solar terms and historical clock conventions.
2. Better English terminology and screen-reader feedback from actual users.
3. A carefully specified timezone / DST input flow, with ambiguous-hour handling, before considering global births.
4. Optional local-model explanations limited to structured facts, if users can show what deterministic explanations cannot answer.

Not planned for the initial release: fate scores, lifespan or disease forecasts, investment timing, chart compatibility judgments, scraping birth records, paywalls, cloud accounts or a sprawling collection of divination systems.

Please report a task you could not finish before requesting more features. A screenshot or a fixture with expected behavior is more useful than an unsupported claim of accuracy.
